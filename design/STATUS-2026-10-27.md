# Evia: where the rebuild stands (27 October 2026)

Read this first if you are picking up work on Evia, whether you are a person or an AI tool such as Codex or Claude.
It records what is built, what was half-done when earlier work sessions were cut off, and what the founder still
has to decide.

## 1. What is on `main` now

From today, `main` holds the **new design**: the visual rebuild to the founder's four mockups (Home + Routine,
Progress, Products, Scan with the hologram). It is merged with everything Ugochukwu Chidera built on `main` since
25 September (56 commits).

How the merge was resolved:

- **Server, data, security, privacy, consent and deletion: `main`'s versions won.** That covers:
  - the Supabase Data API (persistence moved off Postgres/PGlite);
  - the APP_ENV boot guard;
  - P0/P1 security fixes;
  - deletion receipts (completed / pending / failed);
  - the capability-only health check;
  - the user-visible Elohim → Evia rebrand.
- **Look, layout and navigation: the new design won.** Where `main` only changed wording in a screen the rebuild
  replaced (AuthGate, Intro, ChatPanel, ScanPage, router, index.html), the rebuild's screen was kept. Its wording
  already says Evia. Internal code names like `ElohimTurn` and `ELOHIM_*` variables are unchanged on purpose.
- **Re-applied on top of `main`'s new code:**
  - Per-product retailer naming ("Shop at {retailer}") on the Supabase catalogue code:
    - `server/catalogue/{store,offers,picks}.ts`;
    - the new migration `supabase/migrations/20261027000000_catalogue_retailer.sql`, which replaces the old
      `server/db/migrations/016_catalogue_retailer.sql`;
    - `server/db/database.types.ts`.
  - The legacy demo-email rename in `server/demo/seed.ts`.
  - The Data Rights page keeps the design system and focus handling, and now shows `main`'s three deletion
    outcomes (deleted / pending / failed with "your account and data are intact").
- **Removed:** `scripts/dev-db.mjs` (the old PGlite dev database; `main` uses Supabase) and the old three.js scene
  files `src/scene/director.ts` and `src/holograms/portrait.ts`. The rebuild replaced them with `src/stage/` and
  `src/hologram/`. From those two files:
  - **Not carried over:** "Overlay metric badges on captured face" (39393fe), number badges drawn on the user's
    face. It conflicts with the founder's consultation tour, which starts on a clean face. This is a founder
    decision (section 6).
  - **Carried over:** the awaited capture hand-off ("ordered scan capture presentation") is still in
    `src/state/controller.ts`.
- **Libraries:** `@supabase/supabase-js` and `@vercel/speed-insights` were added.
- **Tests:**
  - The rebuild's retailer database test now runs in `main`'s Data API lane, as
    `test/integration/catalogue-retailer.test.ts`. That lane needs the Supabase CLI and Docker, which the founder's
    Mac does not have, so it has **not been run yet**: run `npm run test:data-api` on a machine with Docker.
  - `test/catalogue-browse.test.ts` now replaces the database-backed rate limiter with a pass-through, as `main`'s
    route tests do.

## 2. Why Codex built Evia's character into the old design

The new design was pushed to GitHub on 5 October, but only on the branch `evia-visual-rebuild`. It was never merged
into `main`, because `main` is shared and had conflicting work. Codex (and anyone opening the repo) starts from
`main`, which still had the old design. So on 24-25 October Codex built the founder's MetaHuman into the old
design, on the branch `codex/evia-metahuman`. Now that the new design is on `main`, new work starts from it by default.

## 3. What is built (new design)

- **One design system:** `src/ui/*`, `src/styles/tokens.css`, self-hosted OFL fonts in `public/fonts/`; a
  single shell (`src/shell/*`: sidebar, tablet rail, phone tab bar).
- **Pages:** Home, Routine, Progress, Products, Scan, Learn, Settings, Profile, Privacy, Your data and the legal
  pages, for desktop, tablet and phone.
- **Sample-data mode** (`?sample=1`, or the gate's "Preview with sample data"): every screen filled with
  clearly labelled sample data; it never writes to the server (`src/sample/*`, `localOnly()` in the controller).
- **Rooms:** Blender-rendered room backgrounds (`public/env/*`; scripts in `scripts/blender/`) and the "living
  rooms" WebGL layer (`src/stage/living/*`): lamp flicker, LED coves, plant sway, city windows, sky drift,
  parallax. It is flash-safe, static under reduced motion, and paused off screen.
- **Scan:** the hologram (`src/hologram/*`) and the **consultation tour**, part 1
  (`src/stage/tour-machine.ts`, `src/stage/tour.svelte.ts`, `src/scan/tour-steps.ts`, `src/pages/scan/*`):
  - the face appears clean;
  - one region at a time, a light pulse taps the spot, a line draws to ONE card, the explanation shows in a talk
    card, then the card and line go away;
  - a summary follows;
  - there are Pause, Previous, Next, Show all results and Replay controls;
  - real mode only narrates the reading's own observations, with no numbers and no grade.
- **3D character prototype** (`src/character3d/*`, off by default; Settings or `?character=1`): a faceless
  stand-in mannequin that reaches and points at each region with IK, gaze, idle life, a thinking pose and speech
  beats.

## 4. What was half-done when the work was cut off

1. **Consultation tour, part 2: Evia's own tap, right-side stance and teleport** (`src/character3d/*`).
   - **The tap.** Today a light pulse taps for her. She should touch the spot with her near index fingertip, hold
     about 350 ms, then lift into a presenting palm. She reports `{ kind: 'contact', seq }` exactly once through
     `director.reportTour`, so the line starts at her fingertip.
   - **The side rule.** `periorbitalRight` and `cheekRight` are reached from the RIGHT, everything else from the
     left. Anchors at 1672×941: forehead 846,188; nose 868,332; cheekLeft 747,351; periorbitalRight 958,294;
     chin 873,452.
   - **The two stances.**
     - Left: x −0.9 m, depth 4.36 m, yaw +26°.
     - Right: mirrored about the pedestal's centre plane x = 0.05 m, so x 1.0 m and yaw −26°. Only her position,
       yaw and arm roles change; the model itself is never mirrored.
   - **The teleport, about 1.3 s.** A cyan rim light rises, a dissolve front sweeps up her body with a band from
     cyan `#dcffff` to rose-gold `#f8ad99` and small particles, she switches stance, then re-forms with a front
     sweeping down. It must be WCAG 2.3.1-safe. Under reduced motion it is a 100 ms fade out and in.
   - When the figure is ready she reports `{ kind: 'figure', present: true, caps: { contact: true, teleport: true } }`.
2. **Consultation tour wrap-up.**
   - Append a "## 10. Consultation tour" section to `design/counsel/scan.md` (append-only), listing every new
     tour string verbatim.
   - Keep `test/tour-wording.test.ts` rejecting diagnosis/medical words, and digits in real-mode lines.
   - Update the READMEs.
   - Run an independent review covering experience; accessibility, legal and real mode; and code.
3. **Living rooms: 7 open review findings** (`src/stage/living/*`):
   1. Scrolling forces every room to redraw at the display's full rate, ignoring the 30 fps cap. `layout()` should
      only request a draw when the geometry really changed.
   2. The Scan room moves far more than its spec. Cove breathing should be about ±5% over 8 s, with no outward
      ripple rings on the pedestal and an emitter pulse that does not compete with the hologram's 3 s rings.
   3. Home and sidebar motion is stronger than its spec. Coves should go 0.9↔1.0 over 6-8 s; city windows should
      twinkle at a few % per minute; the candle should vary ±3% over 2-4 s; parallax should be 2-4 px.
   4. Wrapped noise inputs cause one-frame jumps about every 67 minutes, and the shader clock wraps at 7200 s.
   5. GPU cost never stops on low-end hardware. Fix the dither pattern, set DPR 1.0 on low-power devices, run the
      sidebar strip at about 15 fps, and pause after about 2 minutes idle.
   6. The canvas region can go stale. Observe the clipping ancestors, and handle `webglcontextrestored`.
   7. Tilt edge cases on touch devices: listening while still, OS reduced motion, landscape orientation angle,
      and the switch after a refusal.
4. **The real Evia (C6 MetaHuman).**
   - The founder bought a MetaHuman of Evia from a freelancer: "C6", a young woman in plain white nurse-style
     scrubs. The 109 MB source is on the founder's Mac.
   - Codex made a 17.9 MB web version and built it into the OLD design on `codex/evia-metahuman`. That branch also
     has gaze, blinks, speech-driven jaw, an illustrated fallback and lifecycle fixes.
   - **Still to do:** bring C6 into the new design's `src/character3d/` in place of the mannequin. That needs:
     - a bone-name and rest-pose retarget layer (MetaHuman names such as `pelvis`, `spine_01`..`05`,
       `upperarm_l` and `index_01_l` mapped to the logical names the motion code uses);
     - placement and lighting for the consult room;
     - her keep-out boxes recomputed from her rig;
     - a "Show Evia in 3D" switch: on for desktop Scan, off on phones, with the fallback.
   - **Limits:** the C6 export has no facial blendshapes, so speech moves the jaw only, and the hair crown is
     coarse. Ask the freelancer for a re-export WITH ARKit-52 blendshapes and visemes, and better hair cards.
   - **Parked:** the earlier Blender/MPFB Evia (`scripts/blender/evia_*.py`), which independent critics scored
     3-5/10.

## 5. How to run and check

- **Node:** Node 24 (the server runs `.ts` directly).
- **Checks:** `npm run check` (svelte-check), `npm run test:unit` (vitest), and `npm run test:data-api` (needs the
  Supabase CLI and Docker).
- **Bundle:** verify it with `npx vite build --outDir /tmp/evia-build`. `npm run build` runs a legal-content check
  that needs confidential documents which are deliberately not in the repo; never invent legal text to make it pass.
- **Local stack:** `npm run dev` starts Supabase, the API and Vite (see README.md).
- **Previews:** `?sample=1` for the sample-data preview; `?character=1` for the character prototype on Scan.
- **three.js** must stay out of the entry chunk; it loads lazily on Scan only.
